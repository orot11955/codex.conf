# 운영과 충돌 대응

## 명령과 종료 코드

`verify`, `plan`, `install`, `sync`, `doctor`/`status`, `rollback`, `uninstall`, `recover`, `import-state`, `stats`, `lock-skills`, `skills --role <role>`를 제공한다. `diff`나 자동 fetch 명령은 없다. 모델·파일 내용의 자세한 차이는 Git diff와 백업 파일을 직접 검토한다.

install/sync/rollback/uninstall/recover/import-state는 `--sessions-stopped`가 없으면 미리보기다. `--dry-run`은 이 플래그가 함께 있어도 미리보기를 우선한다. `plan`은 항상 미리보기다. 예외적으로 lock-skills는 명시적인 소스 lock 쓰기 명령이다.

종료 코드 0은 해당 명령 성공, doctor의 1은 설치 불일치·drift·CLI 문제, 2는 검증/작업 오류다. 요청한 CLI 검사를 실행할 Codex가 없으면 plan/install은 2, doctor --cli는 1로 종료한다. --cli를 지정하지 않은 verify/plan/doctor는 실제 CLI 성공을 주장하지 않는다. `--skip-cli-check`는 명시적인 탈출 옵션이며 일반 설치 안내에는 사용하지 않는다.

## 기존 링크/스킬 충돌

- 기존 config.toml, AGENTS.md, agents 전체 링크는 대상 저장소에 쓰지 않고 분리하여 설치한다. 제거 시 가능한 경우 원래 링크로 복원한다.
- 이름이 같은 canonical 사용자 스킬은 최초 내용을 백업하고 이 패키지 내용으로 바꾼다. 이것이 원치 않는 스킬이라면 미리보기 단계에서 중단해야 한다.
- 기존 `~/.codex/skills/<name>`는 첨부한 옛 스킬과 콘텐츠 fingerprint가 같은 경우에만 자동 이전한다. 수정된 구형 스킬은 별도 보관·비교 후 직접 판단한다.
- 기존 `.system`과 미등록 다른 스킬을 통째로 옮기거나 삭제하지 않는다. 스킬 루트 **전체**가 링크이면 안전하게 자동 처리하지 않으므로 옛 설치 도구의 복원 절차나 수동 검토가 필요하다.
- 옛 `tester.toml`도 첨부 원본과 정확히 같은 경우만 백업 후 제거한다. 다른 tester는 역할 충돌을 해소하기 전까지 중단한다.
- 다른 파일명이 같은 agent name을 쓰거나 다른 스킬 폴더가 동일 name을 쓰면 자동 선택하지 않는다. 프로젝트·관리자 경로의 모든 중복을 이 도구가 탐색하는 것은 아니다.

## AGENTS.override.md가 있다고 중단할 때

전역 override를 삭제하지 않는다. 내용을 읽어 유지할 규칙을 공통 원본 또는 적절한 프로젝트 지침으로 옮기고, 사용자가 별도로 보관·이름 변경한 뒤 재실행한다. 상위 요구사항·프로젝트 지침은 계속 별도로 적용될 수 있다.

## 설치본 직접 수정

공통 설정은 원본에서 바꾸고 다시 배포한다. 설치된 config의 모델/추론, AGENTS, agents, 관리 스킬을 직접 바꾸면 이후 갱신·제거가 충돌로 멈춘다. 변경 내용을 별도 파일로 보관하고 원본에 반영한 뒤, 관리 대상이 마지막 설치 내용과 다시 일치하도록 검토해야 한다. 충돌을 강제로 덮는 `--force`는 없다.

예외적으로 앱이 config.toml에 추가한 프로젝트 신뢰·UI 등 비공통 키는 다음 sync에서 로컬 값으로 가져온다. machine.toml을 사용자가 직접 편집했다면 그 파일을 로컬 값 전체의 기준으로 우선한다. 앱 변경과 machine 변경이 동시에 있다면 양쪽 내용을 확인해 machine.toml에 필요한 값을 모은다. doctor는 아직 캡처하지 않은 변경을 drift로 표시할 수 있다.

기존 `/Users/...` 홈 전체 trust는 무단 삭제하지 않고 로컬에 보존하지만 doctor에서 경고한다. 신규 공통 배포에는 이를 넣지 않는다. 필요한 프로젝트만 신뢰하도록 기기별로 검토한다.

## 중단/복구

정상 예외에서는 이미 교체한 대상을 원본으로 되돌리려 한다. 복원 중 오류나 프로세스 강제 종료가 있으면 `.codex-conf/pending.json`이 남을 수 있다. 설치 도구와 Codex 작업이 종료되었는지 먼저 확인한다.

```bash
./agentctl recover
./agentctl recover --sessions-stopped
```

`install.lock`이 남아 있으면 파일의 PID/호스트와 실제 프로세스를 확인한 후에만 사용자가 잠금 파일을 제거한다. 살아 있는 다른 설치 프로세스의 잠금을 지우지 않는다. PID 재사용 가능성도 있으므로 숫자만 보고 단정하지 않는다. 잠금 자동 탈취를 구현하지 않았다.

각 target은 같은 디렉터리의 임시 항목으로 복사한 뒤 이름을 바꾸어 교체한다. 여러 파일·여러 루트의 전체 배포를 OS 수준 한 번의 원자적 교환으로 처리하는 구조는 아니다. 중단으로 남은 `.codex-conf-incoming-*`나 `.codex-conf-displaced-*`는 recover가 임의 삭제하지 않으므로 정상 복원을 확인한 뒤 정리한다.

관리 백업의 무결성이 바뀌면 자동 복구하지 않는다. 설정이 망가져도 새 원본의 verify 성공 없이 rollback/uninstall/recover를 실행할 수 있다. 단, 백업 자체가 없거나 손상되었으면 별도 백업으로 복원해야 한다. 디스크 전체 장애를 막는 백업 솔루션은 아니다.

## 정보 보호와 범위

POSIX에서 관리 디렉터리는 0700, 기기 config·machine·상태 파일은 0600으로 생성한다. 기존 로컬 config에 비밀이 하드코딩되어 있으면 로컬 백업에도 남는다. 가능한 환경 변수·OS 자격증명 저장소를 사용하고 `.codex-conf`를 Git이나 공유 폴더에 올리지 않는다. Windows ACL은 별도 확인 대상이다.

상태 파일·백업 해시는 우발 변경을 감지하는 용도다. 같은 OS 계정을 사용하는 공격자가 상태와 해시를 함께 바꿀 수 없다고 보장하지 않는다. 기존 사용자 정의 역할과 스킬, 로컬 설정 자체도 신뢰 경계 밖 입력으로 검토해야 한다. 설치는 사용자 소유 설정의 명시적 변경이며 root/sudo 실행을 권장하지 않는다.

설치 도구는 소스 서명, Gitea 인증, 자동 배포 승인, agent 행동의 완전한 강제, 컨테이너 격리, 세션 동기화, 원격 복구를 제공하지 않는다. 승인된 커밋을 검토한 다음 로컬 적용하는 운영 절차가 필요하다.

## v2 스킬 비활성·업그레이드

현재 설치본을 직접 지우지 말고 새 ZIP을 새 디렉터리에 풀어 verify → plan --cli → 작업 종료 → sync → doctor 순으로 적용한다. 이전 v1의 관리 이력은 자동으로 읽고 새 배포 transaction을 추가한다. source 위치가 바뀌어도 설치본은 복사본이므로 괜찮다.

기존 사용자 스킬의 name은 license/metadata/여러 줄 description이 있더라도 별도로 읽어 중복을 검사한다. 이는 전체 YAML 해석기가 아니라 보수적인 name 추출기다. 지원하지 않는 name 표현/중복 name이면 무시하지 않고 확인을 요청한다. 사용자·옛 Codex 스킬 루트의 일반 중첩 디렉터리와 최상위 링크를 검사하며, 프로젝트/관리자/플러그인 전체를 감사하지 않는다.

새 스킬과 같은 이름이 옛 ~/.codex/skills에 있으면 알려진 v1 이전 원본 hash와 일치하는지 검사한다. 출처를 모르는 신규 이름은 KeyError/자동 삭제 대신 정상 오류로 중단한다. 해당 내용을 보관·검토한 후 이전하거나 별도 이름으로 정리한다.

`skills.config`의 이전 ~/.codex/skills 경로는 새 관리 경로로 옮기면서 enabled 값을 유지한다. 동일한 스킬 경로에 true/false가 충돌하면 자동 결정을 내리지 않는다. 경로가 다른 사용자 별도 스킬 설정과 부모 skills의 다른 옵션은 보존한다.

비활성 설정의 예시는 local.example.toml을 참고한다. 원본과 설치본을 일치시킨 뒤 다른 역할이 정말 이용할 수 있어야 하는 스킬만 활성화한다. doctor의 로컬 비활성 경고는 자동 복구하지 않는다. 이는 의도된 기기 예외일 수 있으며 그대로 둘 수도 있다.
