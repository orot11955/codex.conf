# codex.conf 종합 재검토 · 스킬 통합

배포판: **2026.09.17-unified.2** / 기준: 직전 통합본과 첨부 conf의 실제 실행 정책.

## 결론

모델·역할·최소 위임 정책은 유지했다. 기존 7개에 실용적인 웹 개발·디자인 스킬 10개를 추가하고 역할별 조건을 하나의 원본에서 생성하도록 연결했다. 단순 파일 수집이 아니라 스킬 본문/참고 절을 언제 읽고 어느 역할이 실행할지를 명시했다. 소스와 설치본은 계속 분리되며 Git pull 즉시 실행 환경이 바뀌지 않는다.

추가 10개는 공개 원문을 검토한 **자체 작성 집중 적용본**이다. 원문 전체 규칙/실행 코드/다른 하네스/자동 설치 명령을 복제한 완전한 upstream 배포본이 아니다. 유용한 절차를 self-contained SKILL.md와 작은 references 문서로 정리했다. 각 SOURCE.md에는 원문 위치와 확인한 Git blob ID를, skills.lock.json에는 로컬 내용 hash를 기록했다. 일부는 commit도 확인했으며 blob만 확인한 것을 commit 고정으로 부르지 않는다.

## 보존한 정책

main Luna/max, architect Astra/medium, security Astra/low, scout·executor Luna/low, backend·frontend·test Terra/low, critic Terra/medium. 동시 하위 상한 3, 통상 1~2개. auto_review/fast/interrupt_message, 조건부 security, 소유 파일 단일 담당, main만 Git 쓰기, 하위 재위임 금지와 읽기 전용 검토 역할을 유지했다.

max는 원본 보존값이고 공개 설정 참조·계정 지원과 별개다. 실제 CLI/모델 사용 여부는 이 환경에서 확인하지 않았다. 설정을 다른 모델/추론으로 자동 낮추거나 올리지 않는다.

|---|---|---|
| 역할 연결 | 기존 7개가 전부 수동 호출이며 일부 본문·description도 명시 요청만 요구 | task-orchestration만 수동 유지. 나머지는 좁은 description/조건을 정하고 역할별 지침·네이티브 필터 생성 |

| 출처·참고 | 이름만 등록하면 로컬 참고 누락·떠다니는 원문을 놓치기 쉬움 | source-kind/원문 blob/로컬 hash/참고 파일 존재를 verify에서 검사 |

## 외부 지침을 그대로 넣지 않은 이유

웹 디자인은 기존 브랜드·컴포넌트와 실제 제품 업무를 우선한다. MES/관리 화면에 hero/마케팅 문구·카드·강한 장식색을 강제하지 않는다. 새 화면 설계와 기존 UI 국소 변경을 구별하고 폼·테이블·loading/empty/error·반응형·키보드 흐름을 함께 다룬다.

Vercel 원문에서 매번 최신 웹 지침을 받는 절차는 제거했다. 50행이면 무조건 가상화, native button에 중복 키보드 핸들러, 모든 비인증 필드 자동완성 해제, overflow 감추기로 오류 은폐 같은 일반화도 채택하지 않았다. React 19/새 Next 기능은 프로젝트 버전 검증 없이 이식하지 않는다.

접근성 후보의 큰 텍스트 기준에 px/pt 혼동을 확인했다. W3C에 맞춰 18pt 또는 14pt bold, 약 24 CSS px/18.67 CSS px bold로 정리했다. 24×24 타깃의 예외와 44×44 권고 목표를 구별하며 자동 점수로 WCAG 인증을 주장하지 않는다.

브라우저는 현재 사용 가능한 도구만 사용하며 최신 패키지 자동 설치·개인 프로필 attach·cookie/state 출력·PR 업로드 권한을 포함하지 않는다. task+role named session을 사용하고 다른 세션을 일괄 종료하지 않는다. 디버깅 예제도 전체 env/secret 값을 로그로 출력하지 않도록 작성했다.

## 에이전트별 실행 연결

`policy/skill-routing.toml`이 단일 배정 원본이다. installer는 각 역할의 사용 조건과 actual skill root를 developer_instructions에 추가하고, 등록된 스킬 중 비배정 항목을 skills.config로 false로 만든다. local false는 언제나 보존한다. main의 직접 구현도 동일한 도메인 조건을 따른다.

이 연결은 확률적인 모델 행동을 대체하는 강제 라우터가 아니며 전체 시스템의 보안 allowlist도 아니다. 다른 사용자/프로젝트 스킬은 보존한다. 본문 읽기·도구 사용·결과 보고 계약은 실제 모델 세션에서 확인해야 한다. `/skills` 표시나 config 파싱만으로 수행됐다고 말하지 않는다.

전체 배정과 제외 후보는 ../SKILLS.md, 역할 모델은 ROLE-MATRIX.md, 수용 점검은 RUNTIME-ACCEPTANCE.md에 있다.

## 토큰과 복잡도

설치된 스킬 수는 7→17로 늘었다. 사용 조건과 본문을 분리하고 필요한 참고절만 읽도록 했지만 metadata·역할 지침의 기본 비용은 증가한다. 프론트엔드에 10개를 배정한 것은 매 작업에 10개를 호출한다는 뜻이 아니다. 한 단계의 주 스킬과 필요한 보완만 사용한다. 실제 토큰 감소/속도 향상/디자인 품질 향상은 측정하지 않았다.

stats는 원본/생성 지침의 문자·UTF-8 바이트만 센다. 절대 경로와 프로젝트 설정으로 실제 문맥 크기는 달라진다. 추가 학습·도구 호출·상시 모델 소비는 설치 프로그램에 없다.

## 검증 범위

검증 결과·명령·실행 로그는 TEST-REPORT.md와 test-output.txt에 기록한다. 실제 v1 ZIP을 fixture로 사용하여 v2 갱신, rollback, 최초 uninstall, 개인 설정·외부 스킬 보존을 검증했다. fixture는 tests/fixtures/v1-unified.zip이며 runtime 설치 대상이 아니다.

네이티브 macOS/Windows, 실제 Codex/모델 접근·max 지원·역할 스킬 호출, Playwright browser 동작과 사용자 Gitea는 여기서 검증하지 않았다. 검사 대상에 없는 파일·권한까지 안전하다고 보장하지 않는다. 사용자의 기기·Gitea·원본 ZIP은 변경하지 않았다.
