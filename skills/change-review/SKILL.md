# 변경 검토

## 검토 경계

- 읽기 전용으로 diff와 관련 코드·테스트·설정을 검토한다.
- 구현을 수정하거나 범위를 넓히지 않는다. 재현 시험이 필요하면 main에 필요한 검증을 반환하며 직접 재위임하지 않는다.
- 사실, 추론, 제안을 구분한다.

## 검토 순서

1. 요구사항과 완료 조건을 확인하고 diff의 목적·범위를 파악한다.
2. 변경된 경로마다 정상 흐름, 오류 흐름, 경계값, 호출자·피호출자를 추적한다.
3. 기존 계약, 호환성, 데이터 상태, 설정 기본값, 테스트 누락을 대조한다.
4. 사용자 영향과 회귀 가능성을 기준으로 문제의 우선순위를 정한다.

## 발견 사항 작성

각 발견 사항에는 다음을 포함한다.

- 심각도: 차단, 높음, 보통, 낮음 중 하나
- 위치: `경로:행` 또는 확인 가능한 코드 범위
- 근거: 실제로 문제가 되는 조건과 예상 영향
- 재현 또는 확인 방법: 가능한 경우 최소 입력과 절차

문제가 없으면 검토 범위와 남은 불확실성을 명시한다. 스타일 선호나 근거 없는 가정은 발견 사항으로 올리지 않는다.

## 역할별 선택
사용자 명시 호출 또는 설치된 역할별 사용 조건이 맞을 때만 필요한 절차를 읽는다. 전 단계를 모든 작업에 반복하지 않는다. 역할·파일 소유권과 read-only 제한은 항상 유지한다.
