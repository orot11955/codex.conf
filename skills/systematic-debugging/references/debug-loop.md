# 한 번에 한 가설

먼저 최소 재현을 찾는다. 재현할 수 없으면 어느 조건을 확인했고 무엇이 빠졌는지 명시한다. 간헐 오류를 무조건 timeout 증가/retry로 덮지 않는다.
CI → 빌드 → 산출물 → 배포 또는 UI → API → service → DB의 실제 실패 경계를 구분한다. 각 경계의 입력 형태·상태·오류코드를 필요한 범위로 확인한다. 비밀 데이터의 값은 기록하지 않는다.
동작하는 근접 사례와 비교한다. 다른 라이브러리 버전, request path, feature flag, user/tenant, encoding/collation, 운영체제 차이를 근거로 검토한다.
가설: 'A 때문에 B가 발생한다. C 관측이면 이 가설을 지지/배제한다.' 한 실험에 한 변수를 바꾼다. 실패한 실험의 변경은 사용자 변경과 분리해 안전하게 정리한다. git reset/clean 같은 파괴 명령을 자동 사용하지 않는다.
수정 후 원래 실패 경로와 관련 회귀를 실행한다. 기존 파일을 되돌려 red를 재현할 때도 공유 작업/사용자 변경을 건드리지 않는다. 격리 실험이 불가능하면 red 확인 미실행으로 보고한다.
결과는 관측/가설/변경/검증/한계로 짧게 남긴다. 장애 완화만 수행했다면 근본 원인 해결과 구별한다.
