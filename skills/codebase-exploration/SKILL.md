# 코드베이스 탐색

## 작업 원칙

- 읽기 전용으로 조사한다. 파일 생성·수정·삭제, 포맷터 실행, 의존성 설치, 커밋은 하지 않는다.
- 추측과 확인된 사실을 구분하고, 사실에는 경로와 행 번호 또는 실행 근거를 붙인다.
- 최소 범위부터 시작해 요청과 직접 연결된 호출자, 피호출자, 설정, 테스트로만 확장한다.

## 조사 절차

1. 요청의 핵심 명사와 동작을 검색해 후보 파일을 찾는다.
2. 진입점부터 데이터 흐름, 분기, 오류 처리, 외부 경계를 따라간다.
3. 구성 파일, 생성 코드, 테스트, 문서를 대조해 실제 동작과 의도를 구분한다.
4. 변경 영향이 예상되는 파일·계약·테스트와 미확인 가정을 기록한다.

## 보고 형식

- 현재 동작: 근거가 있는 짧은 설명을 쓴다.
- 관련 위치: `경로:행`과 해당 위치의 역할을 나열한다.
- 영향 범위: 직접 영향과 간접 영향, 확인이 필요한 경계를 구분한다.
- 불확실성: 조사만으로 확정할 수 없는 점과 추가 확인 방법을 쓴다.
- 다음 단계: 설계, 구현, 검증 중 필요한 후속 작업을 제안한다.

## 금지 사항

- 탐색 중 해결책을 구현하거나 파일을 고치지 않는다.
- 근거 없는 구조 변경이나 담당 역할 배정을 확정하지 않는다.
- 테스트 결과만으로 설계 적합성 또는 최종 승인을 선언하지 않는다.

## 역할별 선택
사용자 명시 호출 또는 설치된 역할별 사용 조건이 맞을 때만 필요한 절차를 읽는다. 전 단계를 모든 작업에 반복하지 않는다. 역할·파일 소유권과 read-only 제한은 항상 유지한다.
