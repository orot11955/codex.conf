# 웹 UI 디자인 — codex.conf 적용본

## 적용 조건
새 페이지·컴포넌트의 시각 설계, 또는 사용자가 요청한 UI 개편에 사용한다. API 버그 수정만으로 전체 화면을 재설계하지 않는다.

## 작업 순서
1. 실제 제품, 주요 사용자 작업, 대상 화면 크기, 기존 컴포넌트·디자인 토큰을 확인한다. 제공된 레퍼런스와 프로젝트 지침이 취향보다 우선한다.
2. 기존 화면 개선인지 신규 디자인인지 선언하고 변경 범위를 정한다. 신규 화면만 색·서체·간격·밀도·배치를 짧은 디자인 계약으로 정한다. 기존 UI는 그 계약을 재사용한다.
3. `references/design-contract.md`에서 해당 화면의 항목만 읽고 구현한다. 로딩·빈 결과·오류·비활성·포커스 상태도 실제 동작과 연결한다.
4. 렌더링 가능하면 실제 화면에서 데스크톱·좁은 폭·긴 한글 텍스트를 확인한다. 필요한 경우 배정된 playwright-cli 스킬을 사용한다. 코드만 읽었으면 시각 검증 미실행을 명시한다.

## 경계
업무용 MES/관리 화면에 마케팅 hero, 장식용 대형 카드, 과도한 모션을 강요하지 않는다. 기존 버튼·폼·테이블 패턴을 우선한다. 뉴모피즘·강한 포인트색·특정 유행 스타일을 기본값으로 넣지 않는다. 사용자 브리프가 요구하면 그 방향을 따른다.
폰트·이미지·UI 패키지를 무단 다운로드하거나 도입하지 않는다. 더 독특하게 보이기 위해 접근성·정보 밀도·성능을 희생하지 않는다. 제품 사실·수치·후기는 만들지 않는다.

## 결과
사용한 토큰/컴포넌트, 수정 파일, 구현한 상태, 실제 확인한 viewport와 남은 시각 검증을 보고한다.

출처·변경 범위는 `SOURCE.md`에 있다. 프로젝트 지침·권한·파일 소유권이 이 절차보다 우선한다.
