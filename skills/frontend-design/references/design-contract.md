# 화면별 디자인 계약

## 공통
기존 토큰을 먼저 찾는다. 색(surface/text/border/action/status), 글자 계층, spacing, radius, shadow, focus, motion을 의미 단위로 재사용한다. 새 hex·간격 값을 컴포넌트마다 임의 추가하지 않는다. 새 토큰은 필요한 이유와 영향 범위를 남긴다.
브랜드와 한국어 가독성을 유지한다. 시스템 폰트도 유효한 선택이다. 읽기 어려운 장식체를 본문·숫자 표에 쓰지 않는다. 모션은 상태 변화 설명에만 사용하고 reduced-motion 대안을 둔다.

## 관리 화면·데이터 테이블
사용자가 반복할 작업을 가장 가까운 위치에 둔다. 제목 → 검색/필터 → 주요 작업 → 데이터/페이지네이션의 관계를 분명하게 한다. 테이블 대신 무조건 카드를 만들지 않는다.
숫자·날짜·단위 정렬과 포맷을 일관되게 한다. 선택/일괄 작업, 정렬, 필터 초기화, 열 폭, 빈 결과, 권한 없음, 재시도를 구분한다. 화면 폭이 줄면 열 우선순위나 명시적 수평 스크롤을 설계한다. 데이터를 조용히 잘라 숨기지 않는다.
행 수만으로 가상화를 강제하지 않는다. 페이지네이션·점진 로딩·가상화는 측정과 사용성, 접근성, 인쇄/검색 요구로 선택한다.

## 폼·대화상자
라벨 위치, 필수/선택, 도움말, validation, 오류 위치, 저장/취소 순서를 기존 화면과 맞춘다. placeholder를 라벨 대신 쓰지 않는다. 저장 중 중복 제출을 막되 입력 내용을 잃지 않는다. 오류에서 복구 행동을 제공한다.
Dialog는 이름, focus 진입·복귀, Escape/취소 및 파괴적 작업 보호를 확인한다. 복잡한 편집을 작은 modal에 억지로 넣지 않는다.

## 신규 랜딩·콘텐츠 페이지
한 문장으로 전달할 목적, 1차 행동, 콘텐츠 순서를 정한다. 정보에 맞는 시각적 중심 하나를 선택하고 무관한 장식을 줄인다. 브리프에 없는 통계·고객 로고·평가를 사실처럼 넣지 않는다.

## 짧은 계약 예시
모드: 기존 관리 화면 확장 / 재사용: Button, FormField, DataTable / 토큰: 현재 theme / 변화: 검색 그룹과 빈 상태만 / 확인: 키보드, 390px와 실제 업무 폭, 로딩·실패·긴 값.
