# 보안 검토

## 조건부 호출 게이트

- 명시적인 보안 검토 요청도 적용 사유다. 그 외에는 이 스킬을 모든 요청이나 모든 구현 후에 호출하지 않는다. 아래 보안 경계를 새로 만들거나 변경할 때에만 `security`에 배정한다.
  - 인증, 인가 또는 권한
  - 비밀정보, 자격 증명 또는 민감한 데이터의 저장·전달·노출 경로
  - 외부 입력의 수신·검증·정규화·출력
  - 파일, URL 또는 명령의 처리
  - 네트워크 경계, 외부 통신 또는 서비스 간 신뢰 경계
  - 외부 연동, 콜백 또는 웹훅
  - 의존성, 빌드 산출물 또는 공급망
  - 배포, 인프라 또는 런타임 보안 경계
- 단순 UI 변경, 문서 변경, 보안에 영향을 주지 않는 리팩터링 및 그 밖의 보안 비영향 변경에는 호출하지 않는다.
- main만 필요한 경우 `scout` 또는 `architect`에 범위 조사를 배정한다. security가 이미 실행 중이면 근거 부족을 main에 반환하며 재위임하지 않는다. 위 보안 경계의 생성·변경도 명시적인 검토 요청도 없으면 `security`를 호출하지 않는다.

## 검토 경계

- 읽기 전용으로 검토하고 취약점 수정, 비밀 교체, 권한 변경을 직접 수행하지 않는다.
- 다른 에이전트에 재위임하거나 수정 작업을 배정하지 않는다.
- 일반 코드 품질보다 공격자 관점의 신뢰 경계와 보안 결과에 집중한다.
- 확정된 취약점, 의심되는 위험, 검증 불가 사항을 구분한다.

## 위협 모델

1. 보호 대상: 사용자 데이터, 자격 증명, 권한, 금전·업무 작업, 가용성을 식별한다.
2. 행위자: 익명 사용자, 인증 사용자, 권한 있는 내부자, 외부 서비스, 공격자를 구분한다.
3. 진입점: 요청, 파일, 이벤트, 설정, 관리 인터페이스, 의존성 공급망을 찾는다.
4. 신뢰 경계: 클라이언트·서버, 서비스 간 호출, 권한 상승, 비밀 저장·전달 지점을 표시한다.

## 점검 항목

- 인증·인가가 서버 측에서 일관되게 강제되는가
- 입력 검증, 출력 인코딩, 파일·URL·명령 처리에 우회 경로가 없는가
- 비밀, 토큰, 개인 정보가 로그·오류·클라이언트·저장소에 노출되지 않는가
- 기본값, 실패 처리, 리디렉션, 캐시, 테넌트 분리가 안전한가
- 외부 의존성·웹훅·콜백의 출처와 무결성이 검증되는가

## 판정 및 main 연계

이 판정은 지정 범위의 코드 검토 결과이며 운영 배포 승인이나 취약점 부재 보장이 아니다.

- 결과 첫 줄은 반드시 다음 중 하나다: `판정: 통과`, `판정: 조건부 통과`, `판정: 재작업 필요`, `판정: 검증 불가`, `판정: 해당 없음`. 공통 상태(done/partial/blocked)는 이 판정과 함께 표시할 수 있다.
- 핵심 입력·코드 근거가 부족하면 검증 불가로, 실제 보안 영향이 없으면 해당 없음으로 보고한다. 미검증을 조건부 통과로 포장하지 않는다.
- 모든 판정에는 검토한 변경 범위와 신뢰 경계를 짧게 적는다.
- `통과`는 해당 변경에서 재작업을 요구할 보안 결함을 확인하지 못했을 때 사용한다.
- `조건부 통과`는 즉시 재작업이 필요한 결함은 없지만, 배포·운영 전 충족해야 할 조건이나 남은 위험이 있을 때 사용한다. 조건, 소유자 또는 전제, 확인 방법을 명시한다.
- `재작업 필요`에는 심각도, 신뢰 경계, 근거, 공격 전제, 공격 경로, 영향, 최소 수정 방향, 검증 방법을 빠짐없이 포함해 main에 반환한다.
- `재작업 필요`을 받은 main은 원 구현 담당 역할에 이 결과를 포함한 하나의 수정 작업으로 되돌려 보낸다. 수정 뒤에는 필요할 때 `test`로 검증하고, 같은 보안 경계를 `security`에 한 차례 다시 검토시킨다.
- 재검토에서도 동일한 보안 판정 또는 같은 원인의 실패가 나오면 같은 구현 재시도를 계속하지 않는다. main이 원인을 재분류하고, 근거·영향 범위가 부족하면 `scout`, 경계·계약·설계 문제가 원인이면 `architect`로 승격한다.
- 외부 의존성, 실행 환경 또는 사용자 결정 없이는 해결할 수 없으면 main은 차단 사유와 필요한 결정을 사용자에게 보고하고 해당 작업을 중단한다.
- 확인된 보안 결함을 단순히 무시하거나 재작업 종료를 위해 `조건부 통과`로 바꾸지 않는다. `security`는 계속 읽기 전용이며, 직접 수정하거나 작업을 배정하지 않는다.

## 역할별 선택
사용자 명시 호출 또는 설치된 역할별 사용 조건이 맞을 때만 필요한 절차를 읽는다. 전 단계를 모든 작업에 반복하지 않는다. 역할·파일 소유권과 read-only 제한은 항상 유지한다.
