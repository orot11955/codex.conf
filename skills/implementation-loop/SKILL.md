# 구현 루프

## 시작 조건

다음이 모두 주어진 경우에만 구현을 시작한다.

- 하나의 명확한 목표와 담당 쓰기 에이전트
- 수정 가능 파일 또는 디렉터리의 단독 소유권
- 완료 조건과 검증 방법
- 필요한 설계 결정 또는 탐색 근거

부족한 항목은 기존 코드·요청에서 안전하게 확인한다. 그래도 업무 결정·권한이 부족할 때만 배정자에게 좁은 보완을 요청한다. main의 직접 구현에도 적용할 수 있다.

## 구현 절차

1. 작업 트리와 소유 파일의 기존 변경을 확인하고, 다른 사람의 변경은 덮어쓰지 않는다.
2. 완료 조건을 만족하는 가장 작은 변경을 만든다. 관련 없는 리팩터링, 형식 변경, 의존성 추가를 피한다.
3. 계약·오류 처리·호환성에 영향을 주는 변경은 배정된 범위 안에서 호출부와 테스트를 함께 갱신한다.
4. 지정된 검증을 실행하고, 실패하면 원인을 확인한다. 소유 범위 밖의 원인은 구현으로 우회하지 않는다.

## 검증과 인계

- 검증 명령, 결과, 미실행 항목과 이유를 정확히 기록한다.
- 변경 파일과 각 파일의 목적을 나열한다.
- 완료 조건을 충족하지 못했으면 재현 절차와 막힌 원인을 보고하고, 임의의 범위 확장을 하지 않는다.

## 금지 사항

- 다른 에이전트에게 구현을 재위임하지 않는다.
- 같은 파일을 다른 현재 작업과 동시에 수정하지 않는다.
- 최종 독립 검토나 보안 승인을 스스로 선언하지 않는다.

## 역할별 선택
사용자 명시 호출 또는 설치된 역할별 사용 조건이 맞을 때만 필요한 절차를 읽는다. 전 단계를 모든 작업에 반복하지 않는다. 역할·파일 소유권과 read-only 제한은 항상 유지한다.
